## 🔑 الاستنتاجات الرئيسية

1. **الصفحة الأولى (Page 1):** بعض البلاغات بتحتاج مسح البيانات القديمة وإعادة تعبئتها (Clear + Re-fill)، وبعضها بيتعبى من الصفر.
2. **الصفحة التانية (Page 2):** دايماً نفس الخطوات: مشكلة فعلية + فني + بدون قطع غيار.
3. **الصفحة التالتة (Page 3):** كود عطل + تعليق وهمي + مبلغ = 0 + حفظ وإغلاق.
4. **التعليقات الوهمية** مختلفة حسب نوع المنتج (تكييف ≠ غسالة ≠ ثلاجة...).

### 3. منطق التنفيذ (عقل منفصل): `second-visit.js`
ملف JavaScript منفصل يحتوي على:

- **`executeSecondVisitClose(orderId)`**: الدالة الرئيسية.
- **خطوات العمل:**
  1. الدخول على البلاغ من صفحة Orders (نفس الآلية الحالية).
  2. **Page 1:** قراءة نوع المنتج من الصفحة → تحديد البروفايل → تعبئة الحقول (أو تخطي لو معبية) → Next.
  3. **Page 2:** اختيار المشكلة الفعلية + فني + بدون قطع غيار → التالي.
  4. **Page 3:** كود العطل + التعليق الوهمي + المبلغ = 0 → حفظ وإغلاق.

### 4. التكامل مع الإضافة
- `popup.html`: تبويب رابع.
- `popup.js`: ربط الزر بإرسال `action: 'START_SECOND_VISIT_QUEUE'` للـ content script.
- `content-script.js`: إضافة listener جديد يستقبل الأمر ويُشغّل `second-visit.js`.

## ⚠️ أسئلة مفتوحة — تحتاج رأيك

> [!IMPORTANT]
> ### 1. التعليقات الوهمية
> هل التعليقات اللي حطيتها فوق مناسبة لكل منتج، ولا عندك تعليقات ثابتة بتستخدمها؟
> يمكن نعمل **مصفوفة تعليقات** لكل منتج ونختار منها عشوائي.

> [!IMPORTANT]
> ### 2. بيانات الصفحة الأولى
> في الزيارة التانية، هل **دايماً** بتكون البيانات (علامة تجارية، موديل، سيريال) معبية من الزيارة الأولى؟
> - لو **أيوه** → نتخطى Page 1 ونضغط Next مباشرة.
> - لو **لأ** → محتاج نعرف هنحط بيانات إيه (نسحبها من Technical Review؟ أو نحط بيانات وهمية؟).

> [!IMPORTANT]
> ### 3. رقم العقار والمرفقات
> اللوج بيوضح إنك بتضغط على "رقم العقار" و"اضافة مرفقات" في بعض البلاغات. هل دي خطوة أساسية ولازم نضيفها، ولا دي بلاغات خاصة فقط؟

> [!IMPORTANT]
> ### 4. هل في بيانات إضافية بتتغير حسب البلاغ؟
> ولا كل حاجة ثابتة (Warranty = Out, Amount = 0, Spare Parts = بدون) وبس التعليق وكود العطل هما اللي بيتغيروا حسب المنتج؟
